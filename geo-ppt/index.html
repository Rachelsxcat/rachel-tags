07   /   MEASURE · 持续监测

优化后，如何判断 GEO 是否改善？

使用同一批 GEO 购物问题，在相同测试条件下重复测试，观察 Alexa 对商品的理解和推荐表现有没有变化。
就像考试，前后要用同一套题才好比较。

例如先固定 GEO 购物问题库 V1.0 的 10 个问题，每题测试 2 次，共 20 次有效测试。修改 Listing 后，再按同样规则复测。新问题可收入 V1.1，但不直接与旧版总体数据比较。

同时尽量固定站点、语言、统计规则，并记录价格、库存等变化。
认知准确率：看 Alexa 有没有说错卖点覆盖率：看 Alexa 有没有说到

08   /   ROADMAP · 功能建设

GEO Agent 应该如何分版本建设？

按业务真正能用的能力组织版本，而不是用技术模块名称让听众理解交付内容。

版本 01

GEO 购物问题库与 Alexa 基础诊断

  • 按站点、场景建立 GEO 购物问题库
  • 测试 Alexa 对商品的理解与购物推荐
  • 输出可追溯的基础诊断
交付成果：GEO 购物问题库 + Alexa 测试报告
版本 02

GEO 诊断与 Listing 优化

  • 关联产品事实、Listing、VOC 与竞品
  • 识别信息错误、卖点遗漏和场景差异
  • 生成有证据的字段优化建议
交付成果：诊断报告 + 优化工作台
版本 03

持续监测与问题库迭代

  • 记录修改和前台实际展示版本
  • 定时复测，比较历史 Alexa 回答
  • 形成效果看板并完善问题库
交付成果：监测看板 + 复测报告
与 AWS 最需要确认的 3 项

① GEO 诊断报告究竟输出什么　② 端到端流程如何实际操作　③ 知识图谱相比普通数据关联的具体价值

版本划分是产品建议，不是合同承诺

具体版本数量、交付物、双方职责、验收标准和付款安排，需依据 AWS 与美的最终协商确定。

上述为 AI 产品经理建议的业务功能版本；不是 AWS v5.0 已确定的版本数量或交付承诺。08 / 09
